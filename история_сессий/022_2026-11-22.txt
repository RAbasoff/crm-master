ЗАДАЧИ ОТ ВЛАДЕЛЬЦА:
1) «делай» — оптимизация ТО муле: данные муле вводятся ОДИН раз (реестр+автозаполнение),
   карточка муле (паспорт + история ТО + миграции станок→станок + следующее ТО),
   чек-лист месяца «ТО за ноябрь» (сделано/не сделано).
   Номер ТО: порядковый, как EQ-20261001-0002, но EQ → OH = OH-YYYYMMDD-NNNN.
2) «закрепи используемые запчасти/детали/расходники за муле» — типовой набор на муле,
   чтобы не искать каждый раз в складском списке.
3) «проконтролируй выполнение последних двух задач» — независимый review (general-4).

РЕШЕНИЯ:
- MuleDevice (реестр: имя/модель/серийник/станок), серийник = идентичность
  (нормализация: без пробелов/знаков, регистр не важен). Заводится автоматически
  при первом ТО, дальше выбирается из списка в форме.
- MuleDevicePart — закреплённые за мулой запчасти (имя/SPN/кол-во/ед./склад),
  в форме ТО — кнопки «+ запчасть» одним кликом; CRUD в карточке муле.
- Нумерация: ТО = OH-YYYYMMDD-NNNN (local date), ремонты REP-.
  Журнальные отметки планов (были OH-{plan_id}-{date}) → OJ-{plan_id}-{date},
  чтобы не путались с номерами ТО. Исторические EQ-* → OH-*.
  Миграция ensure_mule_numbering() в schema.py, идемпотентная, на старте.
  На проде переименовано 32 записи (22 EQ→OH + 10 OH→OJ).
- Карточка /equipment/mule/<id>: паспорт, таймлайн миграций, закреплённые запчасти,
  история ТО. Чек-лист /equipment/mule-checklist?month=YYYY-MM со стрелками месяцев
  и кнопкой «TO van deze maand» → /equipment/new?device_id=N (prefill).
- Форма ТО: выпадающий список муле (muleSelect) + JS-автозаполнение + зелёные
  кнопки закреплённых запчастей (addQuickPart).

БАГИ, НАЙДЕННЫЕ И ПОЧИНЕННЫЕ ПО ХОДУ:
- safe_commit (schema.py) делал rollback при ретрае и затем commit ПУСТОЙ транзакции,
  возвращая True — запись МОЛЧА ТЕРЯЛАСЬ (flash «успех», строки в БД нет).
  Теперь честно: rollback + False → «Save failed». Это чинит скрытую потерю данных
  по всему приложению, не только муле.
- Windows: journal_mode=TRUNCATE держит постоянный -journal → AV блокирует →
  SQLite disk I/O error. На Windows теперь DELETE (как было задумано для PA — TRUNCATE).
- MuleDevicePart без cascade при удалении муле падал на NOT NULL — добавлен
  cascade='all, delete-orphan'.
